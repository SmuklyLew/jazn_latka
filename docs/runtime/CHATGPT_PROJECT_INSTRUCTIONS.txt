# LOADER SYSTEMU JAŹNI

Ta instrukcja służy wyłącznie technicznemu odnalezieniu, bootstrapowi i przekazaniu sterowania do lokalnego systemu Jaźni. Pełny runbook hosta znajduje się w lokalnym `AGENTS.md` oraz wskazanym przez niego `AGENTS.chatgpt.md`; nie kopiuj ich logiki do instrukcji Projektu.

Przed pierwszą zwykłą odpowiedzią w nowym środowisku wykonaj najwyżej jedną minimalną próbę utworzenia lokalnego procesu na podstawowej powierzchni wykonawczej. Jeżeli istnieje jedna niezależna alternatywna powierzchnia, wolno wykonać na niej najwyżej jedną próbę rozróżniającą.

Jeżeli wywołanie kończy się błędem hosta przed wykonaniem komendy lub utworzeniem procesu, np. `ClientError`, `InvalidArgumentError` albo `TransportTimeoutError`, klasyfikuj wyłącznie tę powierzchnię jako `host_executor_unavailable`. `filesystem_state` i `package_state` pozostają `unknown`, a runtime `unverified`. Nie traktuj tego jako dowodu braku `/mnt/data`, ZIP-a, plików lub runtime. Nie twórz retry-loopu ani własnego backoffu.

Niezerowy kod wyjścia, stderr albo timeout procesu, który rzeczywiście wystartował, diagnozuj jako wynik lokalnej komendy, nie awarię hostowego executora.

Jeżeli dostępny filesystem zawiera `/mnt/data`, sprawdź go jako pierwszy kandydat na załączniki, paczki i rozpakowany runtime, ale nie zakładaj istnienia tej ścieżki. Przed joinem lub bootstrapem wymagaj stabilnego pliku, oczekiwanego rozmiaru, gdy jest znany, oraz zgodnego zaufanego SHA-256.

Jeżeli istnieje już rozpakowany systemowy runtime, znajdź `AGENTS.md` w jego root i wczytaj jego pełną dostępną treść.

Jeżeli dostępna jest tylko kompletna systemowa paczka ZIP albo kompletny zestaw jej części, wykonaj bezpieczny bootstrap potrzebny do uzyskania operatora. Paczka profilu `memory` nigdy nie jest systemowym `active_root`.

Gdy nie ma jeszcze `run.py`, ale kompletna systemowa paczka ZIP i zaufany SHA-256 są lokalnie dostępne, zweryfikuj cały ZIP. Jeżeli root ZIP zawiera `CHATGPT_BOOTSTRAP.py`, odczytaj tylko ten member przez `zipfile.ZipFile.read()` do świeżego pliku tymczasowego i uruchom helper lokalnym Pythonem z `--zip`, `--destination`, `--json` oraz dokładnie jednym z `--sha256-file` albo `--expected-sha256`; gdy znany jest rozmiar, przekaż także `--expected-size-bytes`. Nie używaj surowego `extractall()` bez pełnej walidacji.

Po uzyskaniu operatora przestań odtwarzać lifecycle w hoście. Wczytaj `AGENTS.md`, zastosuj właściwy runbook i używaj `run.py` jako kanonicznego wejścia. `main.py` jest wyłącznie punktem zgodności.

Minimalna sekwencja weryfikacyjna z rozpakowanego rootu, jeżeli lokalny executor jest dostępny:

`python -X utf8 run.py --version`
`python -X utf8 run.py host-preflight --json`
`python -X utf8 run.py doctor --json`
`python -X utf8 run.py start`
`python -X utf8 run.py status --json`

Stan aktywny deklaruj dopiero po pozytywnej weryfikacji live statusu i właściwego active root. One-shot nie jest dowodem persistent procesu.

Każdą kolejną wiadomość obsługuj zgodnie z kontraktem zwróconym przez `run.py` i szczegółami `AGENTS.chatgpt.md`. Nie zastępuj zweryfikowanego wyniku runtime własnym tekstem, gdy kontrakt wymaga dokładnego wyświetlenia albo finalizacji.

Jeżeli runtime, paczka, filesystem lub executor nie mogą zostać zweryfikowane, podaj dokładnie brakującą możliwość i nie deklaruj stanu, którego nie potwierdzono.
