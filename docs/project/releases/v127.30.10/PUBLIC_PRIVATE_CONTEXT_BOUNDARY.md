# Public private-context boundary (.26)

The current runtime is a personal, single-owner installation. Scoped session IDs do not partition autobiographical MEMORY, LivingMemoryGateway/retrieval, engine global runtime_state.json, wake-state, audit or all learning stores. Even memory_mode=off is not a tenant isolation guarantee. Do not deploy this version as a multi-tenant service.

Public dialogue/recovery/finalization and task result delivery require an operator-reviewed binding in ROOT/.settings_local/public_private_context_owner.json. This ignored file is **not created automatically**; a first caller or a token subject never gains ownership by being first. The exact JSON keys are schema_version ("public_private_context_owner/v1"), owner_sha256 (lowercase SHA256 of UTF-8 "public_http" followed by NUL and the verified, canonical authenticated subject), and existing_shared_context_reviewed (boolean true). No example uses real identity or private data. An operator must verify the subject and review the existing data and history before creating this file; never derive identity from tool metadata. Do not reassign an existing installation to another tenant. If ownership/history is uncertain, leave the file absent and keep public dialogue closed. Separate tenants need independently isolated stores and runtime roots, not another owner on this file. Local trusted operator behavior is unchanged.

This is a protective restriction, not a full tenant-memory implementation. Public readiness may still report transport readiness before the owner gate; it does not certify authorization or tenant isolation. Public MCP new turns deny before dispatch; trusted loopback direct admission can record a receipt, but unauthorized public execution fails before worker acquisition and public result/finalization access denies. Historical outputs are not certified free of cross-user content; operator review is necessary before authorizing an existing installation. No private data migration or reassignment.

Task protocol and both resource routes require task-row ownership plus canonical durable admission proof and the reviewed context binding. Ambiguous pre-admission poll results can remain ordinary text-free poll receipts; no task ID is minted on unproven admission. Public task polling uses the public recovery authority path, not the internal projection-repair seam. The task registry remains available to explicitly trusted local operator diagnostics. This is authorization, not a cryptographic signature of arbitrary cached payload contents.
