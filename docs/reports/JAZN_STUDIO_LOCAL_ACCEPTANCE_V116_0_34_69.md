## P4: what changed

Accepted local Studio final responses remain bound to the pending request until
the Qt event consumer has actually appended the text and acknowledged delivery.
A rejected final, transport break or failed checkpoint update cannot clear the
pending request. Duplicate completion frames in one client instance are ignored.
After a crash before GUI delivery, the checkpoint preserves request_id for the
canonical --daemon-result recovery without resending user text. A GUI crash
after append but before ACK may re-display the same result after restart;
no exactly-once UI presentation is claimed without a durable visible-event log.
The change does not alter ChatGPT host finalization authority.

## P5: what changed

Windows onedir packaging now emits STUDIO_BUNDLE_MANIFEST.json after BUILD_INFO.
All ordinary files in the bundle are hashed, with relative paths and lengths,
excluding only that manifest to avoid self-reference. The read-only verifier
checks for changed, removed and unexpected files and rejects symlink entries.
The historic `current_integrity_match` remains the EXE/BUILD_INFO check; new
`whole_bundle_integrity_match` adds complete folder inspection. Neither result
can set `security_review=PASS`: current P5 safety verdict remains HOLD.

0. Work in a clean throwaway checkout; do not merge the stacked PRs into master.

4. Run `py -X utf8 run.py doctor --json` and `py -X utf8 run.py package-smoke --profile system --json`.
5. With the authorized local Ollama model, perform three accepted turns, restart
   Studio between turns, and use exactly the original request_id to resume
   after a controlled GUI/transport disconnect. Verify turn/trace lineage.
6. Separately test local MCP framing at `/mcp` including raw Content-Length /
   chunked bytes with the normal OS/antivirus configuration. A /healthz PASS
   or tools/list PASS does not establish accepted ChatGPT turn finalization.
7. For P5, build a fresh Windows onedir artifact in a clean isolated root.
   Inspect the new STUDIO_BUNDLE_MANIFEST.json and validate the entire folder;
   do not restore or execute the quarantined historical EXE. Submit the
   historical detection/sample to Avast for adjudication; record detection ID.
   Repeat offline and independent external SYSTEM tests only after safety review.
