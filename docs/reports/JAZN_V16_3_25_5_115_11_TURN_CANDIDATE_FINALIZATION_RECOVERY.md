# v16.3.25.5.115.11 — per-turn model candidates / finalization regression recovery

## Evidence and scope

The Windows Ollama/Gemma3 `jazn-main` runtime audit (2026-10-09) recorded three `runtime_turn_rejected` events with `classified_non_dynamic_response`, zero committed writes, and 16 rejected writes each; earlier accepted turns committed 16 writes. The rejection path is correct fail-closed persistence behavior; do not bypass it. Checkpoint `--last-turn` consequently shows the last committed turn, not the last terminal text. One accepted response included an inline old model timestamp before the runtime's timestamp. Memory handler evidence drafts must remain generation context, never final visible prose. The exact model-candidate rejection reasons were not fully present in the provided audit.

## Implementation

- Resolve one effective model adapter per TurnRequest using its channel command/config; reuse that exact adapter for synthesis and retry, without mutating the daemon engine's shared adapter.
- Prefer a *validated* model candidate over the runtime draft for speech synthesis, even if the draft has a higher heuristic score. An invalid model candidate remains rejected; exact-runtime and external-source policies stay intact.
- Emit bounded candidate evaluation metadata (candidate id, source, score, accepted, violation codes, selected) with no raw model text or private memory excerpt. Keep raw candidate diagnostics out of the public message.
- Strip recognizable model-authored leading timestamp/envelope before constructing the runtime-owned final MessageEnvelope; preserve timestamps appearing later in prose.
- Never select the memory-evidence handler draft as the final visible answer. Retain the truthful fail-closed disclosure if no validated language realization is available.
- Use the candidate's actual provider/model in diagnostic disclosure rather than mislabeling the runtime fallback as an LLM.
- Validate the normalized body that will become visible, not an earlier unsanitized model response.

## Cross-route regression tests

Ordinary dialogue, memory experience, self-state, creative text, capability questions, explicit exact-runtime and external research source constraints, and fallback routes. Preserve transactional rejection and accepted-turn checkpoint sequencing. Use CI on the new branch for Linux/Windows, pyright, release metadata and packaging; do not merge on a subset of green checks.

## Boundaries

This is not evidence that Gemma3 will answer every question correctly or that external ChatGPT MCP is ready. Local model integration does not confer consciousness. Do not include private MEMORY, WAL/SHM, tokens, logs or host workspace files. Metadata files must be regenerated by the canonical release-metadata workflow rather than hand-edited.
