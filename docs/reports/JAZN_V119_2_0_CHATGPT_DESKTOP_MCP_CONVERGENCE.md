# Jaźń v119.2.0 — ChatGPT Desktop MCP convergence

## Summary

v119.2.0 closes a real interoperability defect found during live ChatGPT
Desktop testing against master v113.

The local Jaźń runtime, supervisor, HTTP gateway and stdio MCP target were
healthy. Manual stdio MCP negotiation proved that the server returned the
required canonical tool names. Modern MCP 2026-07-28 also returned correct
model-visible metadata.

The defect was isolated to initialize-era MCP discovery: clients negotiating
2025-11-25 inherited historical app-only/private metadata for several canonical
turn tools from the v76 compatibility definitions.

## Fix

`latka_jazn/mcp/server.py` now normalizes legacy `tools/list` responses for
exactly the canonical ChatGPT turn tools:
- `jazn_status`
- `jazn_generate_visible_reply`
- `jazn_resume_visible_reply`
- `jazn_finalize_reply`

For these tools only, `_meta.ui.visibility` becomes `["model","app"]` and
deprecated `openai/visibility` is removed. `jazn_audit_lookup`, Developer
Mode aliases and other diagnostic surfaces keep their app-only visibility.

## Regression coverage

A new test constructs the real MCP server and executes `initialize`,
`notifications/initialized`, then `tools/list`. It asserts that the four
canonical tools are model-visible while the audit tool remains app-only/private.
Existing modern 2026-07-28 tests continue to own the modern discovery contract.

## Additional master audit findings

- CURRENT_STATE and CURRENT_STEP were stale and still described v107/v112;
- PR #319 is an obsolete historical draft whose only branch-only delta against
  current master is generated release metadata, not missing v109 code;
- portable remote plugin packaging and local Desktop STDIO are distinct paths
  and must not be conflated with a localhost Streamable HTTP plugin;
- current-message app/tool exposure remains host evidence and cannot be proven
  by repository CI.

## Release identity and acceptance

Target: `119.2.0-chatgpt-desktop-mcp-convergence`.

Canonical package-integrity and source-provenance metadata are generated by the
repository workflow, not edited by hand.

Final acceptance additionally requires a fresh ChatGPT Desktop conversation in
which the current message actually exposes all four canonical tools and a fresh
`jazn_status` confirms the expected persistent runtime/version/readiness.
