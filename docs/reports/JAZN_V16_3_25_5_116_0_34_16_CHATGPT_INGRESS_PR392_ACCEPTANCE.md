## Diagnosed issue

`main.py` gates offline dependency preparation with `_ACTIVATION_COMMANDS`. The previous list did not include `mcp-http` (launches an MCP HTTP listener), `supervisor-run` (persistent supervisor), or `host-op-submit` (may submit lifecycle actions). When verified interpreter dependencies were unavailable, these commands proceeded along the diagnostic/non-activation path, allowing later import/launch errors instead of a consistent dependency-readiness failure. This patch routes them through the same canonical `main.py` preparation; no second command parser or daemon owner was added.

`JAZN_DEPENDENCY_AUTOBOOTSTRAP=0` remains the explicit host/operator opt-out. ChatGPT's thin loader must not authorize installation without a separate approved capability. A `ClientError` before process creation cannot be corrected by Python source code. Read-only commands remain `auto_install=False`.
